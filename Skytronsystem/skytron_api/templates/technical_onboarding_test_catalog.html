What changed, and why nothing is "just manual" anymore

Every checkpoint that used to be pure tester-attestation now also runs an automated read of GPSDataLog / GPSemDataLog / OTACommandHistory for this device inside the 5‑minute test window. For SOS/emergency flows (#1–5, 27, 28, 30) and the FOTA check (#6) that automated read is the full pass condition — #6 in particular now reads the firmware-version field straight out of every PVT/HLM packet and requires 2 distinct version strings inside the window, which is direct proof the upgrade took effect rather than just that a command was sent. For the 30 checkpoints that hinge on comparing a measured value to a reference instrument, reading every field of a packet, or a threshold true/false-positive pass (#7–26 except 6, #29, #31–36), the automated read only proves the device was actually transmitting during the test — a real failure mode we hit twice while building this (a demo unit that had sent zero packets, ever). Completion for those requires both the automated snapshot and the tester's own pass/fail to agree.

That confirmation step is also gated now: the API rejects a tester's pass/fail on a hybrid checkpoint outright if the automated check hasn't already found the packet in GPSDataLog/GPSemDataLog. There's no path to confirming a checkpoint the platform hasn't actually seen data for.

Checkpoint #25's regex is also fixed: it used to require a login packet starting with AS (Assam), so any device tested under another state's plate would fail this checkpoint on a perfectly valid packet. It now matches the real structural pattern — ^\$[A-Z0-9]+,\$\d{15}, — regardless of registration prefix.
